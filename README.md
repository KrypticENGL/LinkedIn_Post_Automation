# LinkedIn Post Automation

Writes a LinkedIn post for a marketing client every day — text and image generated by
AI, both screened for NSFW and brand-safety problems, then held in a Telegram approval
loop that only ends when you explicitly say "post it".

Nothing is ever published without two separate confirmations from you.

---

## How a day runs

```
 09:00 cron
     │
     ▼
 Google News RSS ──► Gemini curates 5 distinct topics
     │
     ▼
 Telegram: "Today's hot topics"  [1] [2] [3] [4] [5] [✍️ my own] [🔄 new options]
     │  you tap one
     ▼
 Gemini writes the post  ──►  free image model renders the visual
     │
     ▼
 Safety gate: Gemini reviews the text, and Gemini vision reviews the image
     │                                   │
     │ passes                            │ fails
     ▼                                   ▼
 Telegram: draft + image           auto-repair (up to 2x), then
   [✅ Approve] [❌ Reject]         🚫 blocked — never sent to LinkedIn
     │              │
     │              └─► [📝 text] [🖼 image] [🔁 both] [🗑 cancel]
     │                        │
     │                        └─► you reply with the changes ──┐
     │                                                          │
     │                            regenerate ► re-screen ───────┘  (loops)
     ▼ approve
 "⚠️ Final confirmation"  [🚀 Yes, post it now] [↩️ Wait, go back]
     │                                              │
     │ confirm                                      └─► back to review
     ▼
 Image uploaded to LinkedIn ► post published ► link sent back to Telegram
```

The reject → change → regenerate → re-review cycle repeats as many times as you want,
up to `MAX_REVISIONS`. Each round is given the full feedback history, so the model
doesn't undo an earlier fix while applying a new one.

## What's under the hood

| Layer | Choice | Notes |
|---|---|---|
| Runtime | Node.js 20+ / TypeScript, ESM | |
| Topic discovery | Google News RSS | Free, no API key, no registration |
| Copywriting & curation | Gemini (`gemini-3.7-flash`) | Free tier, `responseSchema` JSON, schema-validated |
| Image generation | Pollinations (default) or Hugging Face FLUX.1-schnell | Both free; Pollinations needs no key at all |
| Safety screening | Gemini text classifier + Gemini vision | Fails closed — an errored check blocks the post |
| Approval | Telegram via grammY, long polling | Two-stage confirmation, persisted state |
| Database | PostgreSQL via Drizzle | Neon / Supabase free tier |
| LinkedIn | 3-legged OAuth 2.0 + versioned Posts API | `w_member_social`, personal profile only |
| Secrets at rest | AES-256-GCM | LinkedIn tokens are never stored in plaintext |
| Web surface | Express | `/health` for an uptime pinger, `/oauth/linkedin/callback` |

### Deviations from `BLUEPRINT.md`

- **Gemini, not Claude.** The blueprint specified the Anthropic API, which has no free
  tier. Gemini's free tier covers all three AI jobs here — curation, copywriting, and
  both safety checks — including the vision call, with no credit card. All model access
  goes through one ~180-line module (`src/ai/gemini.ts`) exposing a single `structured()`
  function, so switching providers again means rewriting that file and nothing else.
- **Topics come from live news, not a static prompt.** The client is a marketing
  agency, so each morning the bot pulls trending business/marketing headlines and asks
  Gemini to turn them into five *distinct* angles you choose from.
- **Free image generation.** Pollinations by default (no key, no billing), with
  Hugging Face as a drop-in alternative behind `IMAGE_PROVIDER`. Note the free tier may
  return a smaller image than the requested `IMAGE_WIDTH`/`IMAGE_HEIGHT`.
- **A safety gate the blueprint didn't have.** Text and image are both screened before
  you ever see them, and a blocked draft cannot reach the publish path at all.
- **Rejection is a conversation, not a dead end.** The blueprint's open question ("should
  rejected drafts be regenerated automatically?") is answered by the recursive loop above.
- **`simple-oauth2` is not used.** The LinkedIn flow is ~100 lines of `fetch`; a
  dependency for it would be more surface area than code.

## Setup

### 1. Install

```bash
npm install
cp .env.example .env
```

### 2. Database

Create a free Postgres on [Neon](https://neon.tech) or [Supabase](https://supabase.com),
put the connection string in `DATABASE_URL`, then:

```bash
npm run db:push
```

**On Supabase, use the pooler, not the direct connection.** The direct host
(`db.<ref>.supabase.co`) resolves to an IPv6 address only, so it fails with `ENOTFOUND`
or `ENETUNREACH` on any network without IPv6 — including most home ISPs and Render's
free tier. Take the **Session pooler** URI from Dashboard → Project Settings → Database
instead. Two things differ from the direct string: the host is
`aws-0-<region>.pooler.supabase.com`, and the username becomes `postgres.<project-ref>`
rather than plain `postgres`.

Percent-encode any reserved characters in the password (`?` → `%3F`, `+` → `%2B`,
`@` → `%40`, `#` → `%23`) — an unencoded `?` silently truncates the URI at that point.

If `db:push` appears to hang, it is waiting on a confirmation prompt that a
non-interactive shell can't answer. Run `npx drizzle-kit push --force`.

### 3. Gemini

Add `GEMINI_API_KEY` from <https://aistudio.google.com/apikey>. The free tier needs no
credit card and comfortably covers this workload — a full day's run is roughly a dozen
calls.

**One caveat worth knowing:** on Google's free tier, submitted content may be used to
improve their products. Everything this bot sends is public-facing marketing copy drafted
from public news, so the exposure is small — but if the client's brief says otherwise,
switch to the paid tier (same key, same code) or run a local model instead.

### 4. Encryption key

```bash
npm run keygen        # prints 64 hex chars
```

Put it in `TOKEN_ENCRYPTION_KEY`. **Changing this key makes stored LinkedIn tokens
unreadable** — you'd need to re-run `/auth`.

### 5. Telegram bot

1. Message [@BotFather](https://t.me/BotFather) → `/newbot` → copy the token into
   `TELEGRAM_BOT_TOKEN`.
2. Send your new bot any message.
3. Open `https://api.telegram.org/bot<TOKEN>/getUpdates` and copy `message.chat.id`
   into `TELEGRAM_CHAT_ID`.

Every handler is locked to that one chat id; anyone else gets turned away.

### 6. LinkedIn app

1. Create an app at <https://developer.linkedin.com/> and associate it with a company
   page (a placeholder page is fine).
2. Under **Products**, request:
   - **Share on LinkedIn**
   - **Sign In with LinkedIn using OpenID Connect**

   Both are self-serve; no Partner Program review is needed for posting to a personal
   profile.
3. Under **Auth**, add your redirect URL — it must match `LINKEDIN_REDIRECT_URI`
   exactly, e.g. `https://your-app.onrender.com/oauth/linkedin/callback`.

   **It must be HTTPS.** LinkedIn rejects `http://localhost`, so there is no
   local-only path through the OAuth flow — deploy first, or expose your local port
   over an HTTPS tunnel such as ngrok. Query strings are stripped and `#` is invalid.
   You can register several URLs, so a tunnel for development and the deployed URL
   can coexist.
4. Copy the client id and secret into `.env`.
5. Set `LINKEDIN_API_VERSION` to a version that has not been sunset. LinkedIn
   supports each monthly version for a minimum of one year and then rejects it
   outright, which surfaces as a deprecation error on every call rather than
   anything that looks like a bug. Current list:
   <https://learn.microsoft.com/en-us/linkedin/marketing/versioning>

### 7. Client profile

Edit `config/client-profile.json`. This is what gives the posts a voice — audience,
tone, expertise, hashtag policy, and an explicit `avoid` list that the safety reviewer
enforces as well as the writer. Spend ten minutes here; it does more for output quality
than any prompt tweak.

### 8. Run

```bash
npm run dev          # watch mode
npm run build && npm start
```

Then in Telegram: `/auth` → approve on LinkedIn → `/topics` to try a full round
immediately instead of waiting for the cron.

## Bot commands

| Command | What it does |
|---|---|
| `/topics` | Fetch today's hot topics right now |
| `/test` | Health check — database, Gemini, LinkedIn token, and quota left |
| `/status` | Everything currently in flight |
| `/recent` | The last five drafts and their outcomes |
| `/usage` | Gemini token usage — by hour, day, week, and pipeline step |
| `/auth` | Connect or reconnect LinkedIn (link expires in 15 min) |
| `/whoami` | Which LinkedIn account is connected, and until when |
| `/deauth` | Release the connected LinkedIn account — revokes the token and deletes it |
| `/retry` | Retry publishing the most recent failed draft |
| `/cancel` | Stop waiting for a reply |
| `/help` | The above, in the bot |

### `/test` and what "quota left" means

`/test` is the one to reach for when the bot has gone quiet and you want to know whether
the service is asleep, the database has gone away, or the API key has been revoked. It
probes each dependency in parallel and reports a status per row: the database with a
`select 1`, Gemini with a model-metadata read that spends no tokens, and the stored
LinkedIn token with its remaining validity.

The quota figures are **counted by this bot, not fetched from Google** — the Gemini API
publishes no quota-remaining endpoint. Every call is already booked to `api_usage`, so
`/test` counts the rows for each model since midnight Pacific (which is when Google's
daily counter rolls over, regardless of `TIMEZONE`) and subtracts that from
`GEMINI_FREE_RPD` / `GEMINI_FREE_RPM`. Two consequences worth knowing:

- **It is a floor, not a guarantee.** A request rejected before it returned token counts
  — a 429, a dropped connection — still cost quota upstream but never reached the table.
- **The limits are yours to keep current.** They default to 10 requests/minute and 250
  requests/day. If your tier differs, set `GEMINI_FREE_RPM` and `GEMINI_FREE_RPD`; the
  live numbers are at <https://ai.google.dev/gemini-api/docs/rate-limits>.

Primary and fallback models are metered separately by Google, so they are listed
separately here.

## Deployment

`render.yaml` in the repo root is a Render blueprint: **New → Blueprint → pick this
repo** creates the service with the right build and start commands, a `/health` check,
and prompts for each secret rather than storing it. Non-secret tuning (model, cron,
timezone, news queries) lives in that file and is versioned with the code.

Two values can only be filled in after Render assigns a URL — set both once the
service exists, then redeploy:

- `PUBLIC_BASE_URL` — e.g. `https://linkedin-post-automation.onrender.com`
- `LINKEDIN_REDIRECT_URI` — that URL plus `/oauth/linkedin/callback`, matching the
  LinkedIn portal's Auth tab character for character

**A free Render service spins down after 15 minutes idle**, and a sleeping service is
running neither the Telegram polling loop nor the 9am cron — so button taps stall and
the daily run is silently skipped.

Mitigations, best first:

1. Point [UptimeRobot](https://uptimerobot.com) or [cron-job.org](https://cron-job.org)
   at `https://your-app/health` every 10 minutes.
2. Move to Render Starter (~$7/mo), which removes spin-down entirely.
3. Self-host.

Note that `storage/` holds
generated images and is **ephemeral on Render** — images are uploaded to LinkedIn at
publish time, so this only matters if a container restarts between generation and
approval. If that becomes a real problem, move image storage to S3/R2.

## Safety behaviour worth knowing

- **The gate fails closed.** If a moderation call errors or Gemini's own safety filters
  decline to review the content, the draft is treated as unsafe, not as passing.
- **Auto-repair is bounded.** A failed draft is regenerated at most
  `MODERATION_MAX_RETRIES` times with the specific failure reason fed back, then it is
  blocked and shown to you with the reason. A blocked draft has no path to publishing.
- **`publishDraft` re-checks.** Even if a draft somehow reached the confirm step, it
  refuses to publish anything whose stored moderation report isn't `safe`.
- **Images are screened for garbled text too**, not just NSFW content — AI image models
  render lettering as nonsense and it looks unprofessional on a client's feed.

## Operational notes

- LinkedIn allows roughly 100 API calls per member per day. One post uses about four.
- LinkedIn only issues refresh tokens to apps approved for them. Without one, the
  60-day access token simply expires and the bot tells you to run `/auth` again.
- Post text is capped at 2,800 characters (LinkedIn's limit is 3,000) and reserved
  little-text characters are escaped before publishing.
